5 2인 동시 편집 ★ — 지금 방식과 확장

여러분 프로젝트의 핵심. 현재는 항목(칸) 단위로 저장 + 마지막 저장이 이김 방식입니다. 진짜 실시간 협업(구글 독스)은 아니지만, 소수 인원엔 실용적이고 여기서 키울 수 있습니다.

사용자 A

row_5 코멘트 수정 → 저장

INSERT … ON CONFLICT DO UPDATE (upsert)

사용자 B

item_12 값 수정 → 저장

기본키 (session, kind, item_key) 가 달라 서로 다른 행

경우 A 서로 다른 칸

✅ 완전 무충돌. 두 저장 모두 그대로 반영 — 사실상 병렬 편집.

경우 B 같은 칸

⚠️ 나중에 저장한 사람이 이김(last-write-wins). 먼저 저장한 값은 조용히 사라짐(경고 없음).

공통 rev + 1

저장할 때마다 세션 버전번호(rev)가 오름 → 상대가 재조회 시 "최신 아님"을 감지.

정직한 한계: ① 같은 칸 충돌을 감지하지 못함 ② 실시간 푸시 아님(재조회 필요) ③ 칸으로 쪼갤 수 있는 데이터에만 잘 맞음(긴 자유 글엔 부적합).

🚀 여러분 프로젝트에서 더 나아가는 법 (권장 순서)

A. 낙관적 락 ★☆☆ 먼저

칸마다 version 을 두고 WHERE version=? 로 저장. 안 맞으면 409 반환 → "누가 먼저 고쳤어요, 다시 저장하세요". 조용히 사라지는 편집이 없어짐. 가성비 최고.

B. rev 브로드캐스트 ★★☆

이미 있는 rev 를 알리기만. 폴링(3~5초마다 rev 확인) → SSE → WebSocket 순으로 즉각성 ↑. 소수 인원엔 폴링이면 충분.

C. soft lock ★☆☆

기존 TTL 락 패턴 재활용 → "지금 A가 편집 중" 배지 표시(막지는 않음). 실무 충돌이 크게 줄어듦.

D. CRDT(Yjs) ★★★ 최후

같은 문단을 동시에 자유 타이핑해야 할 때만. 별도 편집 서버 필요, 복잡도 급증 — 대부분 과함.

한 줄 권고: 지금의 항목단위 upsert + rev 를 유지하고 → A(낙관적 락) 먼저 넣고 → 필요하면 B(폴링) 로 준실시간을 얹으세요. CRDT 는 정말 필요할 때만.

6 권한 판정 흐름 — 누가 무엇을 할 수 있나

모든 변경 요청은 이 판정을 거칩니다. 가드는 작은 함수 3개(uploader / editor / private)로 나뉩니다.

미묘하지만 중요: 편집 거부는 403, 비공개 조회 거부는 404. 403 을 주면 "세션이 있긴 하네"가 들통납니다. 비공개는 존재 자체를 숨겨야 하므로 404 로 답하고, 목록에서도 SQL 로 아예 제외합니다.

7 백그라운드 자동화 — 스스로 돌보는 서버

별도 스케줄러 서버 없이, 서버 프로세스 안 데몬 스레드 3개가 주기적으로 돕니다. 모두 같은 패턴.

💾 DB 백업

온라인 백업 API 로 안전 복사 → integrity_check → 깨진 건 .bad 로 격리. WAL checkpoint 로 -wal 비대 방지.

🧹 청소 + 티어링

고아 세션 회수 · 감사로그 롤오프 · 오래된 파일 S3 이동. DRYRUN 기본 ON(진짜론 안 지움).

📈 리소스 측정

10초마다 CPU/메모리를 24h 링버퍼에 기록. 요청 경로엔 정수 증감만(부담 최소).

메인 죽으면 같이 종료
▶
_started 가드
중복 기동 방지
▶

한 번 실패해도 계속
▶

꼭 챙길 것: 되돌릴 수 없는 자동 삭제엔 DRYRUN 기본값을. 로그로 며칠 지켜본 뒤 확신 서면 켜세요. 이 프로젝트는 아예 "지우기 → 옮기기(S3 아카이브)"로 정책을 바꿨습니다.

8 신원 확인 — 로그인 없이, 나중에 SSO 로

로그인 세션이 없습니다. 요청마다 "누구인지"를 그때그때 알아냅니다(stateless). provider 체인으로 나중에 SSO 로 갈아탈 길을 열어뒀습니다.

확장 포인트: 회사에 SSO 가 생기면 환경변수 하나만 켜면 전환 — 코드 무변경. 단, 헤더를 신뢰하려면 앞단 역프록시가 외부에서 온 같은 헤더를 반드시 제거해야 위조를 막습니다.

9 그대로 훔쳐 써도 되는 패턴 카드

새 프로젝트 초석. 아래 카드를 그대로 따라가면 탄탄합니다.

🧱 층 나누기 + facade

진입점·조립·라우트·보안·신원·DB창구·운영을 분리. DB 접근은 창구 하나로.

🗄 SQLite = WAL + 온라인 백업

PRAGMA 는 커넥션마다, 백업은 backup API(파일 복사 금지).

🔧 손 마이그레이션

CREATE IF NOT EXISTS + table_info 확인 후 ALTER ADD.

🛡 SQL 안전

값은 항상 ? 바인딩, 컬럼명·수정필드는 코드 화이트리스트.

🪪 stateless 신원 + provider 체인

나중에 SSO 전환 여지를 env 로 열어두기.

🚦 가드 분리

조회 거부=404(은닉), 편집 거부=403. CSRF=double-submit 쿠키.

🧾 감사 로그 + best-effort

부수작업(로그·캐시) 실패가 본 작업을 안 막게 try/except.

⏱ 데몬 스케줄러 + DRYRUN

_started 가드 + 위험작업 기본 미실행.

👥 동시 편집

항목단위 upsert + rev → 낙관적 락(409) → 폴링 준실시간.

⚡ 응답 성능

gzip + ETag(304) + 캐시키에 rev(무효화 토큰).
