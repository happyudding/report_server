# client_functions — Honey 클라이언트 기능의 서버 API 이전 자리 (**껍데기**)

> **현재 상태: 빈 껍데기다. 라우트는 등록되지 않으며 서버 동작에 아무 영향이 없다.**
> 구현 대상과 소유자는 **외부 담당자**이고, 이 폴더는 그가 받아 갈 자리와 계약만 잡아 둔 것이다.

## 왜 있나

지금 Honey 클라이언트(사용자 PC, PyQt6)가 실행하는 무거운 일들이 있다 — 입력 파싱,
분석·리포트 생성, 맵 렌더, Excel 왕복 등. 서버 리소스가 넉넉해지면 **이 계산들을 서버로
옮겨 API 로 제공**할 계획이다. 그러면 클라이언트는 얇아지고, 같은 기능을 챗봇·타 시스템·
MCP 도 쓸 수 있게 된다.

다만 이전 대상 코드(`client/report_generator/`, `client/honey_parse/`)는 **이 저장소의
사본이 최신이 아니고 외부 담당자 소유·동결 영역**이다([docs/15_ownership.md](../../../docs/15_ownership.md)).
그래서 이 저장소에서 구현하지 않고 자리만 만들어 전달한다.

## 붙일 때 (외부 담당자용)

기존 [`web_report/`](../web_report/) 가 같은 규약으로 이미 동작 중이니 그것을 본으로 삼는다.

1. `routes.py` 에 라우트를 채운다. Blueprint 이름은 반드시 `public_api_` 로 시작해야
   한다(`public_api_client_functions`) — 관리자 패널의 부하 계측이 Flask endpoint 이름의
   이 접두로만 공개 API 요청을 식별한다. 어긋나면 **모니터링에서 통째로 누락**된다.
2. [`public_api/__init__.py`](../__init__.py) `register_public_api()` 에 등록 2줄을 추가한다.
   지금은 주석으로 자리만 표시돼 있다.
3. 함수 규약을 `contracts.py` 로 만든다(web_report 쪽 `contracts.py` 와 같은 형태).
   그래야 `/capabilities`·MCP tool·관리자 API 탭이 자동으로 따라온다.

## 반드시 지킬 것

`web_report/CONTRACT.md` §4 의 원칙이 그대로 적용된다. 특히:

- **`viewer=None` 을 만들지 않는다** — 비공개 세션이 전부 노출되는 함정이다.
  항상 `""`(공개 세션만) 또는 검증된 uid.
- **요청 스레드에서 무거운 계산을 동기 대기하지 않는다** — waitress 스레드가 13개뿐이라
  하나가 물면 사람 요청까지 굶는다. 오래 걸리는 작업은 `web_report/compute.py` 의
  워커 풀에 얹고 202 + 상태 폴링으로 돌려준다.
- **같은 값을 두 번 계산하지 않는다** — 클라이언트 계산을 서버로 옮길 때 web_report 가
  이미 내는 값(수율·CPK·분포)을 다시 만들지 말 것. 숫자가 갈라지면 사용자는 리포트를
  신뢰하지 않는다.
