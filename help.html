01 · Quick Start

5분 빠른 시작

처음이라면 아래 순서만 기억하세요. Honey가 파일을 읽고, 서버가 Web Report 세션을 보관하며, Honey 안의 보고서 화면에서 결과를 확인하고 의견을 남깁니다.

1
Honey 실행
2
파일 추가·순서 확인
3
모드·제품 정보 입력
4
Web Report 생성
5
분석·의견·공유

  1. Honey를 실행합니다.

    Honey 안에서 보고서를 열어야 PC 계정이 자동 인식되고, 본인 세션의 편집·삭제·권한 기능을 사용할 수 있습니다.

  2. 🆕 New Report를 누르고 파일을 넣습니다.

    Local File Open, Dolphin D1 또는 드래그 앤 드롭으로 파일을 추가합니다. 여러 파일이면 위·아래 순서를 확인합니다.

  3. Product Type과 분석 모드를 고릅니다.

    일반 분석은 Normal, 정확히 두 파일의 전후 비교는 Compare, 한 파일 안의 DUT별 비교는 DUT를 선택합니다.

  4. Web Report를 누르고 업로드 정보를 입력합니다.

    Family, 등록된 Product, LOT ID를 확인하고 Process가 있으면 입력합니다. 업로드가 끝나면 새 세션이 자동으로 열립니다.

  5. Summary → Issue Table → Distribution/Map 순으로 검토합니다.

    전체 결과를 보고, 이슈를 좁힌 뒤 상세 분포와 위치를 확인하는 순서가 가장 빠릅니다. 수정 후에는 각 화면의 저장 상태를 확인합니다.

첫 작업의 권장 경로
단일 파일로 Normal Web Report를 하나 만든 뒤, Summary·Yield·CPK·Issue Table·Distribution·Map Analysis를 차례로 열어보세요. 서버 주소 입력이나 별도 사용자 가입은 필요하지 않습니다.

02 · Concepts

먼저 알아둘 개념

웹 경험이 없어도 아래 네 가지를 구분하면 대부분의 화면을 이해할 수 있습니다.

Honey

PC에서 파일을 선택하고 보고서를 생성하는 업무 프로그램입니다. 내부 보고서 브라우저도 포함합니다.

Web Report

브라우저 형태로 보는 분석 보고서입니다. 여러 탭, 필터, 차트, Map, 코멘트 기능을 제공합니다.

Session

한 번 업로드한 보고서 한 건입니다. 고유한 Session ID를 가지며 의견·Note·권한도 이 단위로 저장됩니다.

report_server

세션과 분석 데이터를 보관하고 화면을 제공하는 서버입니다. 일반 사용자가 직접 실행하거나 설정할 필요는 없습니다.

세션은 “원본 파일”과 다릅니다

구분 의미 사용자에게 중요한 점
입력 파일 검사·측정 데이터가 담긴 로컬 파일 첫 번째 파일이 단위, Item, 상·하한 같은 기준을 정의하므로 순서가 중요합니다.
분석 데이터 Honey가 읽고 Web Report용으로 변환한 데이터 서버가 계산·표시하며, 큰 데이터는 처음 열 때 준비 시간이 필요합니다.
세션 편집 정보 PTE/개발 코멘트, Note, 차트 메모, Trim 매칭, 권한 등 같은 원본을 다시 업로드해도 새 세션이므로 이전 코멘트가 자동으로 따라오지 않습니다.
꼭 기억하세요
URL이 다른 세션은 별도의 보고서입니다. 동일한 파일을 다시 올려도 기존 세션의 의견·Note·표시 설정을 공유하지 않습니다.

상태 표시 읽는 법

사용 가능 현재 화면에서 바로 사용할 수 있는 기능입니다. 권한 필요 Honey 계정 또는 소유자/편집자 권한이 필요합니다. 임시 표시 새로고침하면 초기화되는 분석 보조 기능입니다. 현재 미지원 화면에 보이더라도 연결되지 않았거나 제공되지 않는 기능입니다.

파일 추가와 순서

  • 추가: Local File Open, Dolphin D1 또는 파일 드래그 앤 드롭을 사용합니다.
  • 중복: 같은 파일은 중복으로 추가되지 않습니다.
  • 삭제: 파일 오른쪽의 ✕를 누르거나 전체 Clear를 사용합니다.
  • 순서: 파일을 선택하고 Up/Down으로 바꿉니다. 한 번에 여러 파일을 가져오면 순서 확인 창이 표시될 수 있습니다.
  • Save Name: 기본 이름이 자동 제안되며 필요하면 보고서 목적을 알아보기 쉽게 수정합니다.
첫 번째 파일이 기준입니다.
목록의 맨 위 파일이 Item명, 단위, Lower/Upper Limit 등 분석 기준을 결정합니다. 서로 구조가 다른 파일을 섞지 말고, 기준으로 삼을 파일을 맨 위로 올린 뒤 생성하세요.

Product Type

현재 선택 가능한 Product Type은 MDDI, PDDI, PMIC, SECURITY, TCON입니다. 마지막 선택은 다음 실행에도 유지됩니다.

Honey 시작 시 업데이트 창

새 버전이 있으면 다음 중 하나를 선택할 수 있습니다.

  • Auto install: 자동 설치 후 재실행합니다. 설치 폴더에 쓸 수 없거나 검증 정보가 없으면 비활성화될 수 있습니다.
  • ZIP download: ZIP을 받은 뒤 Honey를 종료하고 설치 폴더에 덮어쓴 다음 다시 실행합니다.
  • Later: 현재 버전을 계속 사용합니다.

업데이트 또는 HONEY 다운로드 버튼이 비활성이라면 배포 파일이 아직 등록되지 않은 상태일 수 있으므로 운영 담당자에게 문의하세요.

04 · Create Web Report

Web Report 만들기

파일 준비 후 분석 목적에 맞는 모드를 고르고, 업무 식별 정보를 입력하여 서버에 세션을 만듭니다.

분석 모드 선택

모드 필요 파일 수 목적 주의점
Normal 1개 이상 단일 Lot 또는 여러 Source의 일반 분석 여러 파일은 동일한 기준으로 비교 가능한 구조여야 합니다.
Compare 정확히 2개 변경 전·후 또는 기준·평가 데이터 비교 파일 목록 첫째가 After, 둘째가 Before로 표시되므로 순서를 확인합니다.
DUT 정확히 1개 한 파일에 포함된 DUT 값별 분리·비교 입력 데이터에 DUT 구분 정보가 있어야 합니다.

생성 순서

  1. 입력 파일과 순서를 최종 확인합니다.

    특히 Compare는 두 파일의 전후 관계, 여러 파일 Normal은 첫 파일의 기준값을 확인합니다.

  2. Normal, Compare 또는 DUT를 선택합니다.

    조건에 맞지 않는 파일 수이면 Honey가 생성을 중단하고 안내합니다.

  3. Web Report를 누릅니다.

    Normal/Compare에서는 Source 이름을 쉼표로 구분해 바꾸는 창이 나타날 수 있습니다. 비워두면 원래 이름을 사용하며, 이름이 겹치면 자동으로 구분됩니다. DUT는 DUT 값으로 이름을 만듭니다.

  4. 업로드 정보를 입력합니다.

    Product Type은 메인 화면 선택값을 사용하고, Family·Product·LOT ID·Process를 지정합니다.

  5. 업로드 완료를 기다립니다.

    성공하면 새 세션이 Honey 중앙 화면에 자동으로 열립니다. 첫 계산은 데이터 크기에 따라 다소 오래 걸릴 수 있습니다.

업로드 정보의 의미

Product Type
제품 대분류입니다. 메인 화면에서 선택한 값을 사용합니다.
Family
Product Type 안의 제품군입니다. Options에서 기본값을 지정할 수 있습니다.
Product
서버에 등록된 Part ID입니다. 제안 목록 또는 포함 검색으로 찾아 선택합니다. 임의 이름이 아니라 등록된 값을 사용하는 것이 원칙입니다.
LOT ID
필수 식별 정보입니다. 첫 파일명에서 추정값이 자동 입력될 수 있으므로 실제 Lot과 일치하는지 확인합니다.
Process
공정/평가 단계 정보입니다. 선택 입력이며, 입력하면 목록 필터와 검색에 활용됩니다.

Family 선택 예시

Product Type Family
MDDIMX, AQUA, CHINA, MDDI_ETC
PDDILCD, PDDI_IT, QDOLED, PDDI_ETC
PMICSOC, MEMORY, DISPLAY, IF, PMIC_ETC
SECURITYNFC_ESE, ESE, Contactless, SECU_ETC
TCONTV, TCON_IT, TCON_ETC
비밀번호나 PIN은 입력하지 않습니다.
현재 Web Report는 Honey가 Windows PC 계정을 자동으로 전달합니다. 별도의 ID/PW 로그인이나 보고서 PIN 절차는 사용하지 않습니다.

생성 후 가장 먼저 볼 것

  • 상단 Product, LOT, Process, Source 정보가 입력 의도와 같은지 확인
  • Summary의 Overall Yield와 Source별 Yield가 원본 검토값과 크게 어긋나지 않는지 확인
  • Yield에서 Step/Bin/TNO 구성이 예상과 맞는지 확인
  • CPK와 Distribution에서 Limit와 Unit이 올바른지 확인
  • Compare라면 Before/After 방향이 맞는지 확인

05 · Excel Workflow

Excel 기능

Honey의 Excel 기능은 목적이 서로 다릅니다. 새 Excel 보고서를 만드는 기능, 기존 Honey Excel을 Web Report로 올리는 기능, 열린 Web Report를 Excel로 내보내는 기능, 서버 Raw Data를 수정하는 기능을 구분해서 사용하세요.

기능 입력 → 결과 주요 용도
Excel Report 측정 파일 → 새 로컬 xlsx 정형 Excel 보고서 작성·배포
Excel Upload 기존 Honey xlsx → 새 Web Report 세션 기존 Excel 결과를 웹 보고서로 전환
Excel Down 현재 Web Report → 새 로컬 xlsx 웹 분석 결과를 Excel로 보관·공유
Rawdata edit 현재 세션 Raw Data → Excel 수정 → 같은 세션 반영 오입력 원본값을 책임 있게 정정

Excel Report 만들기

New Report에서 파일을 준비한 뒤 Excel Report를 누르면 보고서 설정 창이 열립니다.

Select Items

  • 기본적으로 모든 Item이 선택됩니다.
  • 전체 이동, 선택 이동, 더블 클릭으로 포함할 Item을 조정할 수 있습니다.
  • Fail only를 사용하면 Fail 관련 Item만 빠르게 고를 수 있습니다.

현재 지원되는 출력 시트

Summary

보고서 개요와 주요 결과

Yield

전체·Bin·Step 수율

CPK

Item별 공정능력

Fail Item

Fail Item 정리. MDDI에서는 제한

Issue Table

Yield/CPK 이슈 표

Distribution

분포 차트

Histogram (Analysis)

분석용 Histogram

Raw Data

원본 데이터 시트 포함

기본 선택은 Yield, CPK, Distribution입니다. Yield를 끄면 Fail Item과 Issue Table도 사용할 수 없습니다.

분석 옵션

  • Bin1 only: 모든 분석을 BIN=1 데이터로 제한합니다. Bin1 데이터가 없으면 생성할 수 없습니다.
  • Compare Mode: 입력 파일이 정확히 2개일 때만 사용할 수 있습니다.
  • DUT organize: 입력 파일이 정확히 1개일 때만 사용할 수 있으며 Raw Data 포함과 동시에 사용할 수 없습니다.
  • FileName Change: 차트 범례에 표시할 Source 이름을 변경합니다.

완성 파일은 첫 입력 파일이 있는 폴더에 일반적으로 <기본이름>_report_YYMMDD_HHMM.xlsx 형태로 저장됩니다.

기존 Honey Excel을 Web Report로 올리기

  1. 왼쪽의 📤 Excel Upload를 누릅니다.
  2. Honey에서 생성한 xlsx를 선택합니다.
  3. Product, LOT 등 업로드 정보를 입력합니다.
  4. Raw Data가 변환되어 새 Normal Web Report 세션이 생성됩니다.

가능한 경우 Summary의 Engineer Comment, Issue Table의 PTE/개발 Comment와 ETC Item도 함께 가져옵니다.

Excel Upload 필수 구조
Honey 형식의 Issue_table과 하나 이상의 Raw Data 계열 시트가 필요합니다. Raw Data가 없다면 Excel Report를 다시 만들 때 Raw Data 옵션을 켜세요.

오래된 Raw Data 형식에 FAILTNO가 없으면 CPK·Distribution·Map·Pass Yield는 계산되더라도 Yield의 Fail 상세와 Issue Yield 구역은 비어 있을 수 있습니다.

현재 Web Report를 Excel로 내보내기

  1. 내보낼 세션을 Honey 중앙 화면에서 엽니다.
  2. Excel Down을 누릅니다.
  3. 차트에 적용할 Distribution/Histogram Bin1 여부를 선택합니다.
  4. 저장 위치와 파일명을 지정하고 완료를 기다립니다.

Bin1 옵션은 Distribution/Histogram 차트에만 적용되며, 다른 시트의 데이터 범위는 전체 Die 기준으로 유지됩니다. 이 옵션의 Bin1은 BIN=1이면서 규격 내 데이터를 뜻합니다.

Rawdata edit로 현재 세션 데이터 수정

주의: 원본 수정은 되돌리기 이력이 제공되지 않습니다.
Rawdata edit는 표시만 바꾸는 기능이 아니라 세션의 분석 원천을 교체하고 다시 계산하는 작업입니다. 정정 근거와 백업을 확보한 뒤, 업무상 권한이 있는 세션에서만 사용하세요.
  1. 수정할 세션을 Honey 안에서 열고 📝 Rawdata edit를 누릅니다.
  2. Excel에서 필요한 셀만 수정합니다.
  3. Excel 파일을 저장하고 닫습니다.
  4. Honey가 변경을 감지하면 서버에 반영하고 현재 페이지를 새로고침합니다.
  • 변경이 없으면 서버 업로드를 생략합니다.
  • 편집 중 다른 세션으로 이동하거나 Honey를 닫으면 취소 경고가 나타납니다. 계속 편집하려면 이동을 취소하세요.
  • 반영 후 Overall Yield, Limit, Bin/TNO, 주요 이슈가 의도대로 바뀌었는지 다시 확인하세요.

08-1 · Summary

Summary — 전체 결과를 빠르게 파악

  • Major Fail Bins Top 5: 평균 Fail 비율이 큰 Bin 상위 항목

사용 방법

  1. Overall Yield로 보고서 전체 상태를 확인합니다.
  2. Source별 Yield 편차가 큰지 봅니다.
  3. Major Fail Bin으로 주된 손실 원인을 좁힙니다.
  4. Yield 카드를 눌러 Yield 탭의 상세 원인으로 이동합니다.
  5. 편집 권한이 있으면 Engineer Comment에 결론과 후속 조치를 기록합니다.

08-2 · Yield

Yield — Step·Bin·TNO별 손실 확인

수율 손실을 공정 Step과 Bin, FAILTNO까지 내려가며 확인합니다.

화면 구조

  • 전체 수율과 Step별 요약이 먼저 표시됩니다.
  • 상세 표는 데이터에 따라 P1/P2/P3 같은 Step 단위로 나뉩니다.
  • 각 Bin에는 가장 많이 실패한 대표 TNO가 먼저 표시됩니다.
  • ▼를 누르면 같은 Bin의 나머지 FAILTNO를 펼칠 수 있습니다.
  • 전체 펼치기/접기로 여러 Bin의 상세를 한 번에 전환할 수 있습니다.

권장 분석 순서

  1. 손실이 가장 큰 Step과 Bin을 찾습니다.
  2. 대표 TNO와 펼친 TNO의 구성비를 비교합니다.
  3. Item 이름을 눌러 Distribution 상세로 이동합니다.
  4. 같은 Item이 CPK 또는 Map에서도 이상한지 교차 확인합니다.

Item 검색·체크 검색 결과에서 여러 Item을 골라 표시 선택 해제로 전체 목록으로 돌아갑니다.

Item 상세

  • CDF: 데이터 누적 분포를 Source별로 비교합니다.
  • Histogram: 분석용 Histogram과 보고서용 정규분포 곡선을 확인합니다.
  • 통계: n, min, median, max, average, stdev, Cp, CPL, CPU, CPK를 확인합니다.
  • Fail Die: 규격을 벗어난 Die 목록을 확인합니다.
  • 이동: 이전/다음 Item, Back 버튼 또는 Alt + 방향키로 이동합니다.
  • Map 연동: Map에서 선택한 좌표가 있으면 그 Die의 값과 누적 백분율이 CDF에 표시됩니다.

CDF 임시 분석

  • 점 클릭, 영역 선택 또는 Fail 표 체크로 특정 Die를 임시 제외할 수 있습니다.
  • Reset으로 제외를 모두 되돌립니다.
  • X축 Min/Max/Major/Minor를 입력하고 Apply하거나 Auto로 복원할 수 있습니다.
임시 제외와 X축 설정은 저장되지 않습니다.
Item을 바꾸거나 새로고침하면 초기화됩니다. 공식 제외 처리가 아니라 원인 가설을 확인하는 분석 보조 기능으로 사용하세요.

차트 코멘트와 도형

편집자는 CDF 위에 설명을 남길 수 있습니다.

  • 원, 사각형, 선, 텍스트를 그립니다.
  • Undo로 마지막 작업을 되돌리거나 Clear로 모두 지웁니다.
  • 코멘트 문장을 입력하고 저장해야 다른 사용자에게도 보입니다.
  • 기존 텍스트 코멘트는 클릭하여 삭제할 수 있습니다.
  • Note에 붙여넣기를 누르면 CDF와 코멘트를 PNG로 캡처해 Note에 삽입합니다. 편집 권한이 필요합니다.

08-6 · Map Analysis

Map Analysis — 위치·Bin·측정값 분포 확인

Die 위치에 따라 Fail이 집중되는지, Bin/TNO와 측정값이 공간적으로 어떤 패턴을 가지는지 확인합니다.

Bin Map

  • 한 화면의 Map 열 수를 1~8로 조정합니다.
  • 색상 기준을 Bin 또는 TNO로 바꿉니다.
  • 여러 Source와 Step의 Map 카드를 비교합니다.
  • 카드를 누르면 상세 화면이 열리고, 휠/드래그로 확대·이동하며 좌표의 X/Y/값을 확인합니다.
  • 상세 화면에서 더블 클릭하면 화면 배율이 초기화되고, 이전/다음 Map 또는 Alt + 방향키로 이동합니다.
  • 범례를 누르면 특정 Bin/TNO를 강조합니다. DUT 모드에서는 DUT 범례를 눌러 DUT별 패턴을 강조할 수 있습니다.

좌표 선택과 Distribution 연동

  1. SERIAL은 일부 문자열, XPOS/YPOS는 정확한 좌표로 검색합니다.
  2. 여러 필드를 함께 입력하면 모든 조건을 만족하는 결과만 표시됩니다.
  3. 결과에서 Die를 체크해 여러 개를 선택하고 추가합니다.
  4. 선택 Die는 고유 색으로 Map에 강조되고, Distribution의 모든 CDF에도 같은 색으로 표시됩니다.
  5. 필요 없는 좌표는 개별 삭제하거나 Clear로 모두 제거합니다.
좌표 선택은 현재 페이지의 임시 분석 상태입니다.
세션에 저장되지 않으며 새로고침하면 사라집니다. 분석 결론이 필요하면 차트 코멘트나 Note에 별도로 기록하세요.

STDF Map

  • Source를 선택합니다. DUT 모드에서는 DUT 단위로 볼 수 있습니다.
  • Item을 검색해 Die별 측정값을 Map에 표시합니다.
  • 값 범위를 10개 구간으로 나눈 색상 범례로 공간적 분포를 봅니다.
  • 범례를 눌러 특정 값 구간을 강조하거나 Clear로 해제합니다.

STDF Map은 Bin 분류가 아니라 선택 Item의 측정값 크기를 위치별 색으로 나타내는 화면입니다.

08-7 · Trim Analysis

Trim Analysis — Trim 단계 Item 묶음과 변화 분석

INIT/CODE/TRIM/VERIFY 또는 TV2 구조의 연관 Item을 그룹으로 묶고 단계별 분포 변화를 비교합니다.

Product Type별 매칭 규칙

  • MDDI/PDDI의 TV2: TRIM / VERIFY의 2구간 규칙을 사용합니다.
  • 그 외: INIT / CODE / TRIM / VERIFY의 4단계 규칙을 사용합니다.
  • 여러 Source가 있으면 먼저 분석할 Source를 선택합니다.

① Item Matching

  • 자동으로 인식된 연관 Item이 그룹 슬롯에 배치됩니다.
  • CPK<1.33, Shift, Complete 같은 배지로 상태를 빠르게 확인합니다.
  • 편집자는 Item 칩을 끌어 슬롯/멤버/새 그룹으로 옮길 수 있습니다.
  • 검색 팔레트에서 Item을 찾아 추가합니다.
  • ↺ Reset으로 자동 매칭 결과로 되돌립니다.
  • 편집 결과는 현재 세션에 저장되며, 조회자는 읽기만 가능합니다.

② Distribution Analysis

  • 그룹 또는 Item을 체크해 분석 대상을 고릅니다.
  • 페이지당 6개 차트를 3×2 배열로 표시합니다.
  • 각 단계의 분포선, Limit, Shift 범위를 비교합니다.
  • 차트를 PNG로 클립보드에 복사합니다. 환경상 복사가 안 되면 파일 다운로드 방식으로 대체될 수 있습니다.
  • 페이지 이동으로 다음 6개 차트를 확인합니다.

Excel Download

Trim Analysis의 Excel Download는 Item 매칭 결과, 분석 표와 차트 이미지를 포함한 별도 통합 문서를 만듭니다.

08-8 · Note

Note — 세션 안에 분석 근거와 결론 정리

Excel과 비슷한 셀 기반 작업 공간입니다. 분석 요약, 표, 계산식과 Distribution 캡처를 한 세션에 정리합니다.

할 수 있는 일

  • 셀에 텍스트와 숫자를 입력합니다.
  • =A1-B1 같은 기본 수식을 사용합니다.
  • Excel 범위를 복사해 여러 셀에 붙여넣습니다.
  • 글꼴, 색상, 정렬, 테두리 등 셀 서식을 적용합니다.
  • Distribution 상세의 Note에 붙여넣기로 차트 이미지를 삽입합니다.
  • 삽입된 이미지를 끌어 위치를 조정합니다.
Note는 별도 저장입니다.
Issue Table 상단 저장과는 다릅니다. Note에서 편집한 뒤 반드시 Note 저장을 누르고 완료 메시지를 확인하세요. 저장하지 않고 이동하면 경고가 표시될 수 있습니다.

현재 용량 기준

  • Note JSON 전체: 세션당 최대 2MB
  • 이미지 한 장: 최대 2MB
  • 이미지: 세션당 최대 200개

큰 원본 이미지를 반복해서 붙이면 저장 제한에 걸릴 수 있습니다. 분석에 필요한 영역만 캡처하고 오래된 중복 이미지는 정리하세요.

08-9 · Compare

Compare — 두 데이터의 전후 차이 분석

Compare 모드로 정확히 두 파일을 올린 세션에만 나타납니다. 목록 첫 파일은 After, 둘째 파일은 Before로 해석됩니다.

Map

  • 두 Source에 공통으로 존재하는 Die를 좌표 기준으로 비교합니다.
  • Bin이 같으면 초록 계열, 한쪽만 Fail이면 해당 Source 색, 둘 다 Fail이지만 Bin이 다르면 보라색 계열로 구분합니다.
  • 공간적으로 새로 생긴 Fail과 회복된 영역을 찾을 때 유용합니다.

Log

  • Item과 Limit을 After 대 Before로 비교합니다.
  • 추가, 제거, Limit 변경 Item은 항상 보이고 일반 행은 접힌 상태로 시작합니다.
  • 전체 펼치기로 모든 행을 비교합니다.
  • Gap이 10% 이상인 변화는 빨간색으로 강조됩니다.

CPK

  • 평균, 표준편차, CPK의 Before/After와 변화량을 봅니다.
  • |ΔCPK|가 큰 순서로 우선 검토할 수 있습니다.

Bin

  • Before → After의 Bin 이동 건수를 확인합니다.
  • Pass→Fail, Fail→Pass 변화를 분리합니다.
  • Bin별 Yield 차이를 함께 봅니다.
Compare 해석 전 순서 확인
세션 상단 Source명과 Compare의 Before/After가 의도와 반대라면 분석을 계속하지 말고 파일 순서를 바로잡아 새 세션을 만드는 것이 안전합니다.

09 · Server for Users

서버를 사용자 관점에서 이해하기

일반 사용자는 서버 프로그램을 직접 켜거나 주소·포트를 설정하지 않습니다. Honey에 설정된 회사 내부 서버를 이용하면 됩니다.

서버가 하는 일

보관

Web Report 분석 데이터, 세션 정보와 사용자 편집 내용을 저장합니다.

계산

Yield, CPK, Distribution, Map, Trim 등에 필요한 결과와 표시 자료를 준비합니다.

공유

세션 URL, 공개/비공개 상태와 편집 권한을 바탕으로 같은 보고서를 함께 보게 합니다.

처음 열 때 느린 이유

큰 세션은 첫 요청에서 분석 결과나 차트용 데이터를 준비하므로 약 1~2분 이상 걸릴 수 있습니다. 준비된 결과는 재사용되어 다음 접속은 대체로 빨라집니다. Distribution, Map, Trim은 탭을 열 때 추가로 로딩될 수 있습니다.

로딩 중에는 기다려 주세요.
상태가 진행 중이라면 새로고침을 반복하지 마세요. 같은 계산 요청이 겹치면 오히려 완료 확인이 늦어질 수 있습니다. 충분히 기다린 뒤 한 번 새로고침하고, 계속 실패하면 운영 담당자에게 세션 ID와 시각을 전달하세요.

서버 연결이 끊기면

  • Honey 상태 영역에 서버 오프라인 또는 연결 실패가 표시될 수 있습니다.
  • Web Report 생성, 목록 검색, 업로드, 서버 편집과 Excel Upload/Download 일부 기능을 사용할 수 없습니다.
  • 회사 네트워크 또는 VPN 연결을 확인하고 검색 홈을 새로고침합니다.
  • 같은 증상이 계속되면 운영 담당자에게 발생 시간과 오류 문구를 전달합니다.
  • 로컬 파일만 사용하는 Excel Report는 분석 엔진과 Excel이 정상이라면 서버 없이도 동작할 수 있습니다.

사용자가 지켜야 할 운영 원칙

  • 회사에서 안내한 Honey와 내부 네트워크를 사용합니다.
  • 세션 URL과 분석 자료는 승인된 대상에게만 공유합니다.
  • 원본 정정, 공개 전환, 삭제 전에는 영향 범위와 소유권을 확인합니다.
  • 중요한 장기 보관 세션은 중요 표시를 하고, 조직의 별도 보관 정책도 따릅니다.
  • 오류 문의 시 Product/LOT, Session ID, 발생 시각, 화면 메시지를 함께 전달합니다.

10 · Troubleshooting

문제 해결

아래 제목을 눌러 원인과 조치 순서를 확인하세요. 해결되지 않으면 오류 문구를 캡처하고 Session ID, Product/LOT, 발생 시각을 함께 전달합니다.

세션 링크에서 404 또는 “찾을 수 없음”이 표시됩니다.
  1. 일반 브라우저가 아니라 Honey 중앙 화면에서 같은 링크를 엽니다.
  2. 세션이 비공개인지, 본인에게 조회/편집 권한이 있는지 소유자에게 확인합니다.
  3. Dashboard로 돌아가 Product/LOT 또는 Session ID로 다시 검색합니다.
  4. 삭제된 세션인지 소유자에게 확인합니다.

비공개 세션은 권한 없는 사용자에게도 의도적으로 404처럼 보일 수 있습니다.

코멘트 칸이나 저장·삭제·비공개 버튼이 보이지 않습니다.
  1. 상단 사용자 표시가 “읽기 전용”인지 확인합니다.
  2. 일반 브라우저라면 Honey에서 다시 엽니다.
  3. 편집이 필요하면 소유자에게 ⚙ Permissions에서 PC 계정을 추가해 달라고 요청합니다.
  4. 삭제·비공개·권한 관리는 위임 편집자가 아니라 소유자만 할 수 있습니다.
Product 검색 목록을 불러오지 못하거나 업로드 정보가 통과하지 않습니다.
  1. Honey의 서버 상태와 회사 네트워크/VPN을 확인합니다.
  2. Product Type과 Family가 맞는지 확인합니다.
  3. Product는 서버에 등록된 Part ID를 제안 목록에서 선택합니다.
  4. LOT ID가 비어 있지 않은지, 자동 입력값이 올바른지 확인합니다.
  5. 계속 실패하면 Product 등록 여부를 운영 담당자에게 문의합니다.
Compare 또는 DUT 모드가 시작되지 않습니다.
  • Compare는 파일이 정확히 2개여야 합니다.
  • DUT는 파일이 정확히 1개이고 데이터 안에 DUT 구분값이 있어야 합니다.
  • Normal은 1개 이상을 허용합니다.
  • 여러 파일의 Item 구조가 다르면 기준 파일을 맨 위로 옮기거나 호환되는 파일끼리 나누어 생성합니다.
보고서의 Unit, Limit 또는 Item이 예상과 다릅니다.

파일 목록의 첫 번째 파일이 분석 기준을 정의합니다.

  1. 현재 세션의 Source와 입력 파일 순서를 확인합니다.
  2. 기준으로 사용할 파일을 맨 위로 올립니다.
  3. 서로 다른 제품/형식 파일이 섞였는지 확인합니다.
  4. 잘못 생성된 세션을 편집으로 억지 수정하기보다 올바른 순서로 새로 생성합니다.
업로드 후 첫 화면이 오래 걸리거나 탭이 비어 보입니다.
  1. 큰 데이터의 첫 계산은 1~2분 이상 걸릴 수 있으므로 진행 상태를 기다립니다.
  2. Distribution/Map/Trim은 탭을 처음 열 때 추가 로딩될 수 있습니다.
  3. 새로고침을 반복하지 말고 충분히 기다린 뒤 한 번만 새로고침합니다.
  4. 선택된 Source/Item 필터 때문에 결과가 숨겨진 것은 아닌지 Clear 또는 전체 보기를 시도합니다.
  5. 계속 비어 있으면 Session ID와 탭 이름을 운영 담당자에게 전달합니다.
Excel Report, Excel Upload, Excel Down 또는 Rawdata edit가 실패합니다.
  1. PC에 Excel이 정상 설치되어 있는지 확인합니다.
  2. 작업 대상 통합 문서를 모두 닫고 다시 시도합니다.
  3. 파일이 다른 사용자/프로그램에 의해 잠겼는지 확인합니다.
  4. Protected View, 보안 경고 또는 DRM 인증 창이 Excel 뒤에 떠 있는지 확인합니다.
  5. 저장 폴더에 쓰기 권한이 있는지 확인합니다.
  6. 오류 창의 전체 문구를 캡처해 문의합니다.
Excel Upload에서 Raw Data 또는 Issue_table이 없다고 나옵니다.

일반 Excel이 아니라 Honey가 생성한 보고서 형식만 지원합니다.

  • Raw Data 없음: 원본 파일로 Excel Report를 다시 만들고 Raw Data 옵션을 켭니다.
  • Issue_table 없음: Honey 형식이 아닌 파일이거나 필요한 시트가 제거된 파일입니다. 원본 Honey Report를 사용합니다.
  • 시트 이름을 임의로 바꾸거나 일부 시트만 복사한 파일은 피합니다.
Rawdata edit 중 화면 이동/종료 경고가 나타납니다.

Excel 편집이 아직 끝나지 않았다는 뜻입니다.

  • 계속 편집하려면 화면 이동을 취소하고 Excel로 돌아갑니다.
  • 반영하려면 Excel에서 저장한 뒤 통합 문서를 닫습니다.
  • 편집을 포기하고 이동하면 Excel이 강제로 닫힐 수 있고 저장하지 않은 변경을 잃을 수 있습니다.
Issue Comment가 저장되지 않은 것 같습니다.
  1. 편집 셀 밖을 클릭해 자동 저장을 실행합니다.
  2. 상단 디스크 버튼을 누릅니다.
  3. 저장 완료 알림을 확인합니다.
  4. 실패 알림이 나오면 내용을 복사해 두고 네트워크 확인 후 다시 저장합니다.
  5. 저장 완료 전 창이나 Honey를 닫지 않습니다.
Note에 붙인 글이나 그림이 사라졌습니다.

Note는 Issue Comment와 별도 저장입니다. Note 안의 저장 버튼을 눌러 완료를 확인해야 합니다. 용량 제한을 넘겼다는 메시지가 있으면 중복 이미지나 큰 이미지를 줄인 뒤 다시 저장합니다.

Honey 업데이트의 Auto install이 비활성화되어 있습니다.

설치 폴더 쓰기 권한 또는 업데이트 검증 정보 문제일 수 있습니다. ZIP download가 가능하면 Honey를 완전히 종료한 뒤 ZIP 내용을 설치 폴더에 덮어쓰고 다시 실행합니다. 둘 다 사용할 수 없으면 운영 담당자에게 배포 상태를 문의합니다.

예전에 올린 Excel 세션이 현재 상세 화면에서 열리지 않습니다.

과거 legacy xlsx 세션은 현재 Web Report 상세 화면에서 지원되지 않을 수 있습니다. 원본 Honey Excel에 Issue_table과 Raw Data가 있으면 Excel Upload로 새 Web Report 세션을 만드세요.

화면이 좁아 파일명이나 표가 잘립니다.
  • Honey 창을 최대화합니다.
  • 표의 상단/하단 가로 스크롤을 사용합니다.
  • 파일명이나 업로더 위에 마우스를 올려 전체 텍스트가 표시되는지 확인합니다.
  • 필요하면 화면 확대율을 80~90%로 낮추되, 입력 전 현재 행과 열을 다시 확인합니다.

12 · Checklists

업무별 체크리스트

Web Report 생성 전

  • Product Type이 맞다.
  • 첫 파일이 Limit/Unit 기준 파일이다.
  • 파일 순서와 Source명이 의도와 같다.
  • Normal/Compare/DUT 파일 수가 맞다.
  • Product와 LOT ID를 확인했다.

생성 직후 검증

  • 상단 Product/LOT/Process가 맞다.
  • Overall Yield가 원 검토값과 일치한다.
  • Step/Bin/TNO 구조가 예상과 같다.
  • 주요 Item의 Limit/Unit이 맞다.
  • Compare Before/After 방향이 맞다.

공유 전

  • 코멘트와 Note가 저장 완료되었다.
  • 공개/비공개 상태가 목적에 맞다.
  • 수정할 사람에게 편집 권한을 부여했다.
  • 공유 URL이 정확한 세션인지 다시 열어봤다.
  • 민감 정보의 공유 대상이 승인되었다.

Raw Data 수정 전·후

  • 정정 근거와 원본 백업이 있다.
  • 수정할 세션과 LOT를 재확인했다.
  • 필요한 셀만 수정했다.
  • Excel 저장·닫기 후 반영을 기다렸다.
  • Yield/Limit/Bin/주요 이슈를 재검증했다.
