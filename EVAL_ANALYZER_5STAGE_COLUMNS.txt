================================================================================
반도체 불량분석 판단 로직 — 데이터 5단계 + 컬럼 의미
(엔지니어가 판단하던 흐름을 그대로 코드로 옮긴 구조)
================================================================================

핵심: 엔지니어의 fail 판단은 아래 5단계로 갈린다.
  1 INDEX        무엇을 보는가      (식별·조회)
  2 RAW MEASURE  무엇을 가져오는가  (테스트지의 "사실")
  3 JUDGMENT     어떻게 calc 하는가 (엔지니어의 "렌즈" = 룰이 임계하는 대상)
  4 VERDICT      무엇을 도출하는가  (기계 판정)
  5 HUMAN        사람이 어떻게 판단 (정답 = ground truth)

  [3↔4 사이] = 룰 로직(thresholds.json + signatures.yaml + bin_taxonomy)
               → 데이터 컬럼이 아니라 (3)→(4) 변환기.

흐름 한눈에:  1·2·3 (기계 입력/계산) → 4 (기계 판정) → 5 (사람 정답)
  · 4 는 5 와 "같은 모양" → 예측(4) vs 정답(5) 비교 → calibration 피드백 루프
  · 노하우는 전부 (3)에 쌓인다 (사실을 어떻게 읽느냐)


================================================================================
[1] INDEX — 무엇을 보는가 (식별·조회 키, 닫힌 집합: 일찍 신중히 확정)
================================================================================
  product_type    제품군(MDDI/PDDI/PMIC/SECURITY). spec·임계값이 제품군별로 분기.
  product         제품명.
  lot_id          로트 식별자. 그 item 의 특정 발생(instance)을 가른다.
  process         공정 라인.
  revision        EVT 버전.
  item_canonical  정규화된 항목명(공백/대소문자/표기차 제거). 조인·이력·RAG 의 "진짜 이름".
                  └ 예: "VREF_TRIM" 과 "vref_trim " → 둘 다 vref_trim 으로 통일.
  item_base       phase 접미사를 뗀 파라미터 본체. = family(단계 묶음) 키.
                  └ 예: vref_init / vref_trim / vref_code / vref_p2 → base 모두 "vref".
  item_phase      측정 단계/조건 접미사.
                  └ 예: init / code / trim / p2. (같은 LOW_CPK 라도 phase 로 의미가 달라짐)
  bin             불량 분류 번호. 두 역할:
                  · 식별: 같은 item·다른 bin = 다른 fail 현상 → 정체성=(product,item_canonical,bin)
                  · 의미: bin 번호가 분류 인코딩(예 bin18=defective, bin31=abnormal)
                          → 같은 신호라도 bin_class 로 status 보정(bin_taxonomy 참조)
  (limit)         lsl/usl = spec 한계. INDEX 의 맥락이자 (2)원천값. spec_margin(3) 계산 기준.


================================================================================
[2] RAW MEASURE — 무엇을 가져오는가 (테스트지의 "사실": 직접측정/표준통계)
================================================================================
  cpk, cp         공정능력 지수(표준 보고치). ※엄밀히는 계산값이나 "표준 수치"라 RAW 로 둠.
  yield           수율.
  fail_value      실패 측정값(한계 이탈한 실제 값).
  mean            평균.
  stdev           표준편차.
  kurtosis        첨도(꼬리 두께의 표준 모멘트).
  count           개수(측정/불량 수).
  lsl, usl        하한/상한 spec.
  x_pos, y_pos    wafer 좌표(공간 패턴 분석의 원재료).
  site (= DUT)    측정 site. site 간 비교(장비/handler 의심)의 단위.
  per-DUT 값      DUT 하나하나의 측정 원시값. ※저장 안 함 — 계산 시점에만 메모리에서 사용.

  ※ (2)는 "사실". (3)만 다시 계산해도 (2)는 재수집 불필요(공식 변경 ↔ 원천 분리).


================================================================================
[3] JUDGMENT METRIC — 어떻게 calc 하는가 (엔지니어의 렌즈 = 룰 입력)
================================================================================
  spread_norm          정규화 산포 = robust_σ(MAD)/(USL−LSL). "산포가 spec 폭 대비 얼마나 넓나".
  skewness             비대칭도(medcouple, robust). 부호=꼬리 방향(±). 어느 쪽 spec 으로 치우쳤나.
  outlier_ratio        이상치 비율(IQR fence / modified-z>3.5). "몸통 대비 얼마나 튀나".
  cdf_gap              ECDF(누적분포) 점프 크기. = 부분모집단 사이 갭(값이 끊겨 있음).
  density_gap          분포 밀도의 골(이봉 사이 저밀도 구간). 두 모집단 혼입 신호.
  spec_margin          (mean − 최근접 limit)/stdev. spec 까지 σ 몇 배 여유인가.
  site_cpk_delta       site 간 cpk 편차. 큼 = 특정 site/장비 의심.
  yield_pct            수율 비율(판단용 정규화 수율).
  code_edge_hit        CODE/TRIM 값이 range 끝(레일)에 박힘 = 트림 포화/클리핑.
  edge_fail_ratio      wafer edge 영역 불량 집중도.
  tail_ratio_hi/lo     상/하 꼬리가 몸통 대비 얼마나 늘어졌나(한쪽 꼬리 위험).
  modality             분포 형태(uni=단봉 / bi=이봉).
  family_corr          같은 base 의 phase 간 per-DUT 상관(예 INIT↔TRIM).
  phase_recovery_rate  INIT fail 이 P2(재측정)에서 회복된 비율.
  wafer_pattern        공간 패턴 분류(EDGE/CENTER/CLUSTER/RANDOM).
  n_dut                표본 수(min-n 가드: 작으면 고차모멘트 룰 비활성, confidence=low).

  ※ estimator 는 표준 robust 기본값, 임계값은 절대 하드코딩 금지
    → ① spec/robust scale 로 정규화(무차원) ② calibration 분위수로 결정.


[3↔4 사이] 룰 로직 (데이터 아님, 변환기)
  thresholds.json   (3) 지표의 임계값(product_type 별 override). 분위수 보정.
  signatures.yaml   (3) 조합 → named 고장 모드(아래 (4) signatures). 선언형.
  bin_taxonomy      bin → bin_class(defective/abnormal…) → status 보정.


================================================================================
[4] VERDICT — 무엇을 도출하는가 (기계 판정)
================================================================================
  status             triage 심각도: CRITICAL / MAJOR / MINOR / MONITOR.
  signatures         발화한 고장 시그니처(아래 목록). 지배 signature 가 status 결정.
  reason_codes       발화한 원시 신호 코드(LOW_CPK, SOURCE_IMBALANCE 등).
  confidence         판정 신뢰도(데이터 충분/표본 수 반영).
  data_completeness  어떤 데이터로 판정했나(예: cpk/산포 결측 시 low → "yield 만으로 판정").

  signature 예시:
    EQUIPMENT_SUSPECT  site 간 편차 큼 → 장비/handler/site 의심
    MEAN_SHIFT         mean 이 한쪽으로 치우침 → 공정 센터링
    WIDE_DISTRIBUTION  산포가 넓음(spread)
    SEVERE_OUTLIER     소수 극단값이 튐(outlier)
    TAIL_RISK          한쪽 꼬리가 spec 근접(tail)
    BIMODAL            이봉 분포(두 모집단)
    SUBPOP_GAP         cdf_gap/density_gap → 부분모집단 갭
    CODE_RAIL          code_edge_hit → CODE/TRIM 레일 포화
    SPEC_TOO_TIGHT     산포 작고 중앙인데 cpk 낮음 → spec 자체 문제
    EDGE_FAIL          wafer edge 불량 집중
    GROSS_FAIL         불량률 매우 높음(전 source) → 근본/설계 이슈
    TRIM_INEFFECTIVE   TRIM 후에도 산포 안 줄음(family)
    RETEST_RECOVERY    P2 가 INIT fail 회복 → test marginal 의심(family)


================================================================================
[5] HUMAN — 사람이 어떻게 판단하는가 (정답 = ground truth, 엔지니어 입력)
================================================================================
  root_cause      근본 원인(enum): equipment / process / design / spec / unknown
  disposition     조치(enum):       retest / trim / spec_review / monitor / scrap
  signature_tag   사람이 지목한 고장 시그니처(선택, 위 (4) 목록 중. 모르면 비움)
  comment         자유 텍스트 — 엔지니어의 분석방향 메모.
                  └ RAG 의 본체. 과거 comment 가 검색되어 새 케이스 코멘트의 근거가 됨.

  ※ 엔지니어는 "규칙"을 넣는 게 아니라 "판정 라벨"만 넣는다.
    규칙(룰/임계값)은 누적된 (5)에서 시스템이 calibration/mining 으로 채굴한다.


================================================================================
요약
================================================================================
  1 INDEX        : 누구를(무엇을) 보는가          ← 식별·연결
  2 RAW MEASURE  : 어떤 사실을 가져오는가          ← 원천
  3 JUDGMENT     : 그 사실을 어떻게 읽는가         ← 엔지니어 노하우(룰 입력)
  4 VERDICT      : 그래서 기계가 어떻게 판정하나   ← status/signature/confidence
  5 HUMAN        : 사람은 어떻게 결론짓나          ← root_cause/disposition/comment(정답)

  · 판단의 "기준"은 (3)→(4): 판단 지표를 룰이 평가해 결과를 낸다. (1)은 대상을 정할 뿐.
  · (4) 가 (5) 에 가까워지도록 (3)의 임계값을 (5)로 보정 = 학습이 아니라 calibration.
